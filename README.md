# 抖音账号工作台

员工用各自的账号打开同一个网站，查看和修改服务器上的同一份账号、手机卡、手机设备和发布记录。

## 现在怎么用

- 网站：http://42.192.45.194
- 总管理员初始登录名是 `board-owner`，改名后使用新登录名。密码不在这个仓库里，由管理员自己保管。
- 总管理员可以在「返回看板」后的页面右上角选择「修改我的登录名」，输入新登录名和当前密码。改名保留原人员身份、权限及全部业务资料，不修改密码；所有旧登录会立即失效，需要用新登录名和原密码重新登录。新登录名必须是3至40位字母、数字、点、横线或下划线，不能与已有人员重复。当前密码连续验证失败5次后，需等待15分钟再试。
- 总管理员在「子账号与权限」里创建员工，并分配办公室。员工只能看到分给自己的办公室。没有分配办公室的员工看不到业务资料。
- 桌面壳只是打开上面的网站。安装包和便携版在 GitHub Release：https://github.com/fang1776358081-arch/DouyinAccountBoard/releases/tag/v0.3.0
- 已经安装 0.3.0 及以上版本的桌面壳，会在有新版本时自动下载，重启后换上。
- 采集目前关闭。

## 继续开发

### 办公室三双表导入

总管理员在「管理工具 → 导入 / 导出」中，同时上传“账号情况表”和“工作进度表”的 CSV 或单工作表 Excel，也可选择粘贴两份 CSV 文本。先联合预览，再输入“导入办公室三”确认。两份资料合计不超过8MB，不含公式（Excel 请先粘贴为值）。

- 目标固定为办公室三；只安全新增，已有账号、手机设备、发布电脑和发布格逐字段保留。真实抖音号已在其他办公室或待分配区时列为冲突，不移动、不复制。
- 来源缺少抖音号、重复、发布格已占用或无法唯一匹配时，保留为待核对，不猜测覆盖。可以重复预览，已经存在的资料不会重复新增。
- 预览单独列出“缺失昵称核对”：仅在唯一真实抖音号匹配且明确归属办公室三时，对比系统占位昵称与来源昵称。此处只供核对，确认安全新增也不会补写旧昵称；正式补全需另外确认。冲突按账号、设备、电脑、发布格分别计项，不等于缺失账号数。
- 密码、远程控制信息、影刀账号和固定IP不导入；停发栏、颜色和数量不当作每日发布记录。手机编号只提供来源参考，不自动确认设备登录或手机卡位置。
- 预览绑定本人且30分钟过期；确认前资料变化会要求重新预览。确认在同一事务内完成，并检查原记录、其他办公室、待分配区及全局发布批次未被改变；失败时整批回滚。
- 如果来源表中的电脑已经存在、但仍待分配，可在预览中单独核对列出的电脑，输入“仅分配电脑到办公室三”整批确认归属。此步骤只调整这些电脑的归属和对应可见范围，不动账号归属或原业务字段；已有其他办公室归属的电脑不能这样改。确认后原预览作废，必须重新预览再导入。

### 开发与发布

改网页、接口或服务器代码之后，提交并推送到这个仓库的 `main`。服务器大约每 2 分钟拉取一次，有更新就重启网站。员工刷新页面就能看到，不需要重新安装桌面壳。

改桌面壳程序本身时，还要按 `.cursor/skills/ship-douyin-board/SKILL.md` 打包并发布新的 GitHub Release。只改网页时不要发桌面壳安装包。

本地测试使用项目里的合成数据，不要连接服务器上的数据库。

### 性能与列表范围

- 账号清单每页显示50条，页脚显示筛选总数和页码；搜索仍覆盖全部授权筛选结果。“选中本页”仅选择本页，“选中全部筛选结果”和表头全选覆盖全部筛选结果，统计、导出范围不因分页缩小。
- 看板仅渲染当前页面；发布矩阵仍保留全部筛选电脑，不会因账号表分页隐藏发布安排。
- 新网页按所选日期读取发布版本信息，切日期时同步获取该日的发布状态与版本。只减少无关日期的技术版本元数据，不删除历史发布记录；旧接口默认完整读取保持兼容。
- 性能对照使用项目内合成数据，报告必须区分本地SQLite/浏览器渲染与真实PostgreSQL、网络、生产环境。未经实际测量，不以单用户卡顿或低CPU直接建议升级服务器。

## 自动同步日志

服务器同步脚本的可维护源码在 `ops/douyin_board_sync.py`，安装后由原来的 `douyin-board-sync.service` 和约每2分钟一次的定时器调用。同步器本身需按服务器维护流程单独安装；仅推送网站代码不会自动替换同步器。安装不依靠网站进程执行，也不改数据库。

- 每轮同步有独立的 `run_id`，记录北京时间、步骤开始/结束、耗时、退出码和更新前后的提交号。
- 能区分没有新版本、工作区有改动而跳过、拉取超时、DNS/连接/TLS/认证/HTTP错误、快进失败、重启和就绪检查失败。拉取失败不会重启当前网站，下一轮仍会重试；重启指令超时会标记为状态待确认，不擅自回滚或停站。
- 日志不保存原始 Git 输出、命令参数、环境变量、URL、令牌或业务文件名，只保存固定错误分类及必要的数字诊断信息。
- 日志同时写入 systemd journal 和 `/var/log/douyin-board-sync/events.jsonl`。专用目录仅root可访问，日志文件权限为0600；单文件上限2MiB，保留当前文件及5份轮转文件，避免无限增长。

在服务器上查看最近同步记录：

```sh
journalctl -u douyin-board-sync.service --since "20 min ago" -o cat --no-pager
tail -n 100 /var/log/douyin-board-sync/events.jsonl
```

按同一个 `run_id` 查看该轮的所有步骤。`run_finish` 给出最终结论；只有更新、重启和就绪检查均成功才算更新完成，定时器处于运行状态不等于本轮更新成功。专用日志写入失败会尝试向 journal 输出固定诊断，并以非零退出码提示本轮记录不完整；若两种日志通道都故障，仍需检查 systemd 服务状态。

## 手机、手机卡与账号处理

- 每台实物手机只属于一个办公室。同办公室内手机序号不能重复，不同办公室可以分别有“29号手机”。新增时先选办公室再填序号；序号和设备内部身份分开保存，旧设备编号、账号、手机卡和换机历史不会自动迁移或合并。
- 手机设备页支持办公室筛选，关联和移卡选择显示“办公室＋序号＋实物代次”。旧的待分配或多办公室设备保留为待核对；仅改备注等资料可保留原归属，明确改归属时须指定一个办公室，目标办公室同号冲突会拒绝。返修旧机重新编号沿用原手机的唯一办公室。
- 手机设备的「故障 / 换机记录」按每台实物保存记录。同一个29号可以由新手机接替，旧手机的卡、账号和售后历史不会自动归给新机。
- 「登记设备故障」中只勾选实际受影响的账号，可以确认同时暂停养号计时；账号原有状态、注册手机号和发布位置分别保留。
- 手机卡的「移卡 / 核对位置」分别支持实际插入另一台手机、核对卡仍留在故障旧机、取出放入卡盒。可以记录卡槽1、卡槽2，核对旧位置时还可以标记卡槽待确认。原表的文字位置保留参考，不自动当成已确认位置。
- 账号的「登录恢复」记录最后登录实物、准备恢复到的手机、受阻原因、负责人和跟进日期。只有勾选已实际登录成功，才更新已确认登录设备。移卡不会自动完成账号恢复。
- 「新机补齐此编号」登记新的实物；「返修手机重新编号」可以让旧手机在复检后使用新的未占用编号。新旧实物及原编号的历史继续保留。
- 故障处理可以暂挂并填写下次跟进日期。结案前逐个账号明确恢复成功、暂不恢复或无法恢复，并填写结案说明；恢复失败不自动等同于账号封禁。
- 手机卡运营商支持中国移动、中国联通、中国电信、中国广电、民生电信、长城移动，选择「其他」还可以填写具体名称。

## 设备流程结构升级

设备流程新增五张业务表，PostgreSQL 迁移文件为 `migrations/postgresql/0004_device_workflow.sql`。它需要通过受控迁移流程执行，启动网站不会自动执行 PostgreSQL 迁移；已有三个迁移文件及其校验值保持原样。

发布这一版本前，需要由服务器维护流程安排数据库结构升级。仅推送 `main`、等待服务器拉取代码，不能代替数据库迁移；PostgreSQL 仍是旧结构时，新版本的启动校验会拒绝启动，不能直接推送上线。不要从本机连接生产数据库来执行升级或测试。

不要把密码、令牌、数据库文件、日志或 `.env` 写进仓库。数据库密码在服务器的 `/etc/douyin-board.env`，只有服务器本机能读。
