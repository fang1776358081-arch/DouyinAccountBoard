# 抖音账号工作台

员工用各自的账号打开同一个网站，查看和修改服务器上的同一份账号、手机卡、手机设备和发布记录。

## 现在怎么用

- 网站：http://42.192.45.194
- 总管理员登录名是 `board-owner`。密码不在这个仓库里，由管理员自己保管。
- 总管理员在「子账号与权限」里创建员工，并分配办公室。员工只能看到分给自己的办公室。没有分配办公室的员工看不到业务资料。
- 桌面壳只是打开上面的网站。安装包和便携版在 GitHub Release：https://github.com/fang1776358081-arch/DouyinAccountBoard/releases/tag/v0.3.0
- 已经安装 0.3.0 及以上版本的桌面壳，会在有新版本时自动下载，重启后换上。
- 采集目前关闭。

## 继续开发

改网页、接口或服务器代码之后，提交并推送到这个仓库的 `main`。服务器大约每 2 分钟拉取一次，有更新就重启网站。员工刷新页面就能看到，不需要重新安装桌面壳。

改桌面壳程序本身时，还要按 `.cursor/skills/ship-douyin-board/SKILL.md` 打包并发布新的 GitHub Release。只改网页时不要发桌面壳安装包。

本地测试使用项目里的合成数据，不要连接服务器上的数据库。

## 手机、手机卡与账号处理

- 手机设备的「故障 / 换机记录」按每台实物保存记录。同一个29号可以由新手机接替，旧手机的卡、账号和售后历史不会自动归给新机。
- 「登记设备故障」中只勾选实际受影响的账号，可以确认同时暂停养号计时；账号原有状态、注册手机号和发布位置分别保留。
- 手机卡的「移卡 / 核对位置」分别支持实际插入另一台手机、核对卡仍留在故障旧机、取出放入卡盒。可以记录卡槽1、卡槽2，核对旧位置时还可以标记卡槽待确认。原表的文字位置保留参考，不自动当成已确认位置。
- 账号的「登录恢复」记录最后登录实物、准备恢复到的手机、受阻原因、负责人和跟进日期。只有勾选已实际登录成功，才更新已确认登录设备。移卡不会自动完成账号恢复。
- 「新机补齐此编号」登记新的实物；「返修手机重新编号」可以让旧手机在复检后使用新的未占用编号。新旧实物及原编号的历史继续保留。
- 故障处理可以暂挂并填写下次跟进日期。结案前逐个账号明确恢复成功、暂不恢复或无法恢复，并填写结案说明；恢复失败不自动等同于账号封禁。
- 手机卡运营商支持中国移动、中国联通、中国电信、中国广电、民生电信、长城移动，选择「其他」还可以填写具体名称。

## 设备流程结构升级

设备流程新增五张业务表，PostgreSQL 迁移文件为 `migrations/postgresql/0004_device_workflow.sql`。它需要通过受控迁移流程执行，启动网站不会自动执行 PostgreSQL 迁移；已有三个迁移文件及其校验值保持原样。

发布这一版本前，需要由服务器维护流程安排数据库结构升级。仅推送 `main`、等待服务器拉取代码，不能代替数据库迁移；PostgreSQL 仍是旧结构时，新版本的启动校验会拒绝启动，不能直接推送上线。不要从本机连接生产数据库来执行升级或测试。

不要把密码、令牌、数据库文件、日志或 `.env` 写进仓库。数据库密码在服务器的 `/etc/douyin-board.env`，只有服务器本机能读。
