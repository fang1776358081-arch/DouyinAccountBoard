# 表格同步试点：使用、验证和启用

这是新流程的开发候选说明。代码存在不表示正式网站已更新，也不表示生产结构已经启用。

## 页面与权限

独立入口为 `/table-sync.html?office_id=three`。新页只读取本模块状态，不先读取完整看板。办公室三的账号中心和今日工作使用五个任务入口；其他办公室保持原入口。旧导入路由保留兼容，新试点不会调用旧版会创建设备及发布格的安全新增流程。

只有总管理员能开启、暂停、结束试点，生成预览、确认同步、处理批次问题或生成回退。普通人员沿用原办公室查看范围，不获得批量更新权限。默认关闭；缺少可选结构时明确提示，不执行启动迁移，不影响原页面。

## 操作流程

1. 将同轮腾讯在线文档分别导出为单工作表 Excel 或 CSV，合计不超过8MB。选择“安全新增”或“更新已有账号”，填写本轮标记并选择双表。
2. 点击生成预览。读取文件有实际进度，分析和生成预览显示阶段；可以取消尚未提交的预览。取消不会撤销已提交的写入。
3. 核对账号、字段前后值和来源行。安全行默认勾选，冲突行不能选择。可单独取消安全行；列表每页50条，所选数量覆盖全部预览页。
4. 输入页面给出的确认语句。仅确认的允许字段会写入，同事务保护检查失败时整批回滚。纯冲突或无变化也能保存“不改账号”的核对回执。
5. 复查并按权限导出批次回执，处理未处理、已确认无需处理、已人工修正三种核对状态。来源文件原文不长期保存。

预览30分钟过期，绑定操作者、办公室、日期、恢复代次、试点修订、资料摘要。资料变化后重新预览。结果不明时界面锁定新操作，只查询或重试原请求编号；刷新恢复仅保存用户/办公室绑定的请求索引，不存凭据、上传原文或变更值。不要因为后来的一次失败提示就断言原请求没有成功。

## 数据边界

- 精确使用真实抖音号字符串；保留前导零和大小写，不修剪身份空白、不靠昵称/手机编号猜测。
- 任一表或系统重复、跨办或待分配同号、明确双表矛盾均待核对，不自动合并或抢占。
- 来源空白不清空。账号可修改字段仅昵称、注册手机号、注册日期、明确映射的状态，以及满足唯一现有办公室电脑和空位置条件的资料登记电脑。会触发养号变化的行须另行处理。
- 实际发布安排、身份、大小号、手机、卡、养号和发布历史以及人工备注始终保留。新账号不建立设备/卡/发布关系。
- 负责人、使用、违规、业务类型、门头和受控来源信息保存为独立资料，不从卡主、保管人或来源手机序号猜关系。
- 工作台仍是日常业务权威系统，表格用于阶段性受控核对。

## 回退

先从原批次生成反向预览，再核对和确认。仅恢复仍等于该批写入后值的字段；后续人工修改列冲突，不强行覆盖。新增账号有后续修改或依赖时不删除。回退也有固定请求编号和独立回执。

同一原批次最多有一个成功反向回执，部分选择会保留未选项，不得理解为可反复回退剩余行。当前同批移出资料槽位后又尝试占用该槽的新增行，可能被保守列为冲突；可分批处理，不自动腾挪账号。

代码回退应撤销本次来源/试点入口并保留请求核对与批次读取能力，不删除六张扩展表，不恢复整库影响其他办公室。先核对所有结果不明请求，再改变写入口。

## 结构启用条件（本轮不执行）

`0007_table_sync.sql` 只追加六张表及相应索引，没有真实数据、默认开启记录或权限扩张。旧0001～0006文件保持原哈希，运行时继续接受完整且哈希正确的v4/v5/v6；v7只有完整记录及扩展表齐全才能启动。

正式启用须按原服务器维护流程：核对真实运行提交及schema版本，暂停写入/自动同步，生成服务器本地受保护备份并验证可还原；确认完整v6基线后受控执行0007，核对版本记录、表/索引和原业务行及权限不变。若服务器仍为v4/v5，先单独评估既有升级，不能为启用本模块默默跳过前置升级。检查运行身份对新增表的最小必要权限，恢复原运行与定时器状态，再核对后端和静态版本、未登录拒绝、办公室隔离。不要从本机直连生产数据库，也不要启动应用自动迁移。

代码与结构启用分开：获得代码发布授权后，可先推送兼容旧v4/v5/v6的网页与后端。缺少0007时新接口明确返回尚未启用，禁止新流程写入；原页面照常使用。推送和服务重启不会自动执行0007，也不会自动开启办公室三试点。

仅在上述维护、备份、迁移及隔离验证完成，并取得结构启用与试点开启授权后，才开启办公室三；不对其他办公室开放。不使用通用“迁移全部最新”命令代替本次受控版本计划。

## 验证口径

`run_isolated_tests.py` 支持 `test_table_sync`、`test_table_sync_http`；前端运行 `node test_table_sync_ui.cjs`、`node test_account_pilot_ui.cjs` 和 `node test_pilot_shell.cjs`，并沿用原分页、编辑、自动同步、范围及压缩回归。

真实本机PostgreSQL使用 `probe_postgresql.py --table-sync-checks`，探针只连接新建且已核验的回环集群。可用 `tools/pilot_browser_fixture.py --root .synthetic-tests/<全新目录>` 在本机真实浏览器检查合成页面，绝不读取客户表格或生产库。

本机SQLite、假DOM/Fetch和本机PostgreSQL结果必须分开报告。正式冷暖启动、办公电脑筛选/滚动、真实网络及1～2名办公室三员工连续三个实际工作日的试用，需要上线后另行验收；不能据合成结果宣称已证明线上秒数。
